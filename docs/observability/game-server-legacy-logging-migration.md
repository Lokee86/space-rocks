# Game-server legacy logger migration map

This is the frozen Step 1 checklist for production call sites of
`logging.Server`, `logging.Network`, `logging.Rooms`, and `logging.Game`.
The inventory is source-only: generated files, tests, documentation examples,
and the checked-in `game-server` binary are excluded.

Inventory total: 124 calls — 16 server, 51 network, 17 rooms, and 40 game.
Every call appears once below. Each file belongs to one owning implementation
stream even when a file currently uses more than one legacy category.

The frozen implementation streams are:

- server lifecycle
- networking
- rooms
- simulation/devtools

## Trace and field shorthand

- `ST`: one UUID startup trace owned by `cmd/game-server`; use it for startup,
  dependency, and primary runtime failures.
- `CT`: one UUID connection trace created with each WebSocket session; use it
  when no packet or match trace exists.
- `PT`: the incoming packet/command `TraceID`, falling back to `CT` when the
  packet cannot be decoded or has no trace.
- `MT`: the room's current match trace (`room.match.CurrentTraceID()`).
- `RT`: a UUID room-operation trace threaded from the request, or generated by
  the room owner for lifecycle work that has no request trace.
- `LT`: a UUID cleanup/lifecycle trace owned by the room manager.
- `—`: the replacement event does not require a trace.

`IDs` lists the identifiers required on the canonical record. `Code` identifies
the stable `error_code`, `failure_mode`, or `reason_code` value to emit; raw
error text remains diagnostic message context only. `Remove` means no canonical
replacement is intended.

## Contract-gap decision and verification

No contract gap was found. Every retained replacement uses an existing event
in `shared/contracts/observability/events.toml`, existing top-level context
identifiers, or bounded free-form fields such as `failure_mode`, `error_code`,
`reason_code`, `dependency`, and `transport`. No new event or field should be
added in Step 2, and no generated Go contract change is required.

Implementation constraints frozen by this map:

- Generate/thread UUID traces at the owning lifecycle seams listed above; do
  not weaken an existing event's `trace_required` rule.
- Preserve readable `player_id`, and use `room_id`, `match_id`, and
  `session_id` only when the owning seam has them.
- Do not emit raw packet payloads or raw error values as structured fields.
- Do not create a canonical event for removed high-frequency success/debug
  output.
- Keep each file in exactly one stream: server-lifecycle, networking, rooms,
  or simulation/devtools.

Verification target for the implementation streams: after migration, a source
scan of production Go files has zero `logging.Server`, `logging.Network`,
`logging.Rooms`, or `logging.Game` calls, while the generated observability
contract remains unchanged and data-sync observability checks stay clean.
